Lesson 0001 · RHCSA · Operate running systems

Check a service and its journal

On the new job, the first question in an incident is the one you already ask on Windows Server: is this application running, and what did it just log? On Linux that is one service check, then the journal.

This is the first task in the administrator course. The EX200 study points call it “start, stop, and check the status of network services” and “locate and interpret system log files and journals.”

The Windows picture

In Services, the Status column says Running or Stopped. Startup type is a different column: Automatic is not the same fact as Running. Event Viewer then shows the recent lines for that application. Linux splits those the same way.

Read the status

Type this at a shell. payments-api stands in for whatever the service is named on the host.

systemctl status payments-api

systemctl(1) says status prints human-readable runtime status, then the most recent journal lines. The default excerpt is 10 lines. Two lines matter on a first look:

  • Loaded. enabled means the service is included in boot, the way Startup type Automatic does. disabled means it will not start at boot. You can still start it by hand.
  • Active. Usually active or inactive. failed means this run failed: a crash, an error exit, or a timeout. The cause is written in the journal underneath.
● payments-api.service - Payments API
   Loaded: loaded (/usr/lib/systemd/system/payments-api.service; enabled; preset: enabled)
   Active: failed
 Main PID: 2144

Oct 12 09:14:02 app01 payments-api[2144]: Error: cannot connect to database

That service is set to start at boot, and this run failed. The log line says why. status does not show earlier boots. The manual says earlier invocations come from journalctl --unit=.

Read the rest of the log

When the 10-line excerpt is not enough, ask the journal for that one unit:

journalctl -u payments-api -n 50 --no-pager

journalctl(1) says -u shows messages for that unit, and -n limits how many recent events you see. --no-pager prints and returns, instead of opening less. Only root, and members of systemd-journal, adm, or wheel, can read the system journal. If the command says you are not allowed, that is access, not a wrong service name.
